# RAG Data Preparation & Chunking Pipeline

Production-ready пайплайн для подготовки данных и нарезки на чанки (Chunking) для систем Retrieval-Augmented Generation (RAG). Проект спроектирован с упором на воспроизводимость, отказоустойчивость и прозрачность происхождения данных (Data Lineage).

## 🏗️ Архитектура проекта

Проект разделен на два независимых пайплайна (паттерн **Facade**), чтобы соблюсти принцип единственной ответственности (Single Responsibility).

### 1. Data Preparation Pipeline (Подготовка данных)
Отвечает за извлечение чистого текста из сырых файлов и первичную фильтрацию:
*   **Loading** (`LlamaIndex`) — сканирование директории, фильтрация по расширениям, генерация стабильных хэшей (SHA-256).
*   **Parsing** (`Unstructured`) — семантическое извлечение элементов (Title, NarrativeText, таблицы).
*   **Cleaning** — удаление boilerplate (cookie-баннеры, меню), расчет первичных Quality Signals.
*   **Normalization** (`spaCy`) — Unicode NFKC, приведение текста к единому виду.
*   **Deduplication** — комбинированный подход: `SHA-256` (для точных дублей) и `MinHash LSH` (для near-duplicates).
*   **Structuring** — сборка документов, генерация метадаты Lineage и Hierarchy.
*   **Exporting** — атомарная запись в `JSON`/`JSONL` и генерация `manifest.json`.

### 2. Chunking Pipeline (Нарезка на чанки)
Подготавливает очищенные документы к этапу генерации эмбеддингов (embeddings):
*   **Loading** — потоковое чтение `dataset.jsonl` с Pydantic-валидацией.
*   **Splitting** — **Semantic Block Packing**. Текст разбивается на логические блоки (абзацы), которые затем упаковываются в чанки с жестким контролем лимита токенов (`tiktoken`).
*   **Validation** — **Fail-fast** валидация (остановка при критических ошибках), расчет Quality Signals (плотность текста, доля мусора).
*   **Exporting** — **Транзакционное** сохранение файлов через временную директорию (защита от рассинхрона данных).

## 🛠️ Стек технологий
*   **Python 3.10+**
*   **Pydantic** (строгая валидация конфигурации и метадаты)
*   **Prefect** (гранулярная оркестрация пайплайнов)
*   **MLflow** (трекинг экспериментов, параметров и метрик)
*   **LlamaIndex / Unstructured** (загрузка и парсинг)
*   **Tiktoken** (подсчет токенов по моделям OpenAI)
*   **Datasketch** (MinHash для поиска near-duplicates)
*   **Pytest** (юнит-тестирование)

## 📌 Ключевые инженерные особенности
*   **Semantic Block Packing:** Текст не режется слепо каждые N символов. Сначала выделяются абзацы (Semantic Blocks), которые затем упаковываются в чанки. Это предотвращает разрыв таблиц и логических блоков.
*   **Точные Offsets (Attribution):** Каждый чанк хранит координаты `chunk_start_char` и `chunk_end_char` относительно исходного документа. Это необходимо для точного цитирования (highlighting) в финальном UI.
*   **Гранулярный Prefect:** Каждая стадия (load, split, validate, export) — это отдельная `@task` с возможностью ретрая и трекинга в UI.
*   **Транзакционный экспорт:** Все файлы (`.json`, `.jsonl`, `manifest.json`) пишутся во временную папку и только потом переносятся в целевую. Если упадет запись манифеста — не останется «битых» чанков.
*   **Стабильные ID:** Генерация идентификаторов вынесена в утилиту `stable_id` на базе SHA-256.

## 🚀 Как запустить

1. Установите зависимости:
```bash
pip install -r requirements.txt
```

2. Запустите пайплайны последовательно (по умолчанию используется Prefect):
```bash
# Шаг 1: Подготовка данных (создаст dataset.jsonl в data/prepared/)
python -m src.rag_prep.cli prepare

# Шаг 2: Нарезка на чанки (создаст chunks.jsonl в data/chunks/)
python -m src.rag_prep.cli chunk
```

3. Для отладки можно запускать пайплайны без оркестратора (напрямую):
```bash
python -m src.rag_prep.cli prepare --no-prefect
python -m src.rag_prep.cli chunk --no-prefect
```

## 🧪 Запуск тестов
Для проверки стабильности генерации ID и валидации моделей выполните:
```bash
pytest tests/
```

## 📊 Мониторинг (MLflow)
Для просмотра метрик экспериментов (параметры нарезки, количество чанков, ошибки валидации) запустите локальный сервер MLflow:
```bash
mlflow ui
```
Затем откройте в браузере `http://127.0.0.1:5000`.
